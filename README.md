# iClever Corporate Frontend

Корпоративный веб-интерфейс для управления обучением, онбордингом сотрудников, оргструктурой и базой знаний организации в экосистеме **iClever.ai**. Интерфейс доступен на трёх языках: **русском, казахском и английском**.

Данный репозиторий представляет собой **автономное frontend-приложение**, независимое от бэкенда и инфраструктуры. Результаты внутреннего аудита и список изменений — в [`AUDIT_REPORT.md`](./AUDIT_REPORT.md).

## 🚀 Быстрый старт (локальная разработка)

Для локального запуска **не требуется** запускать микросервисы бэкенда или Docker. Все API-запросы обслуживает встроенный эмулятор бэкенда (**Mock API**, `src/mocks/`).

### 1. Установка зависимостей
```bash
npm install
```

### 2. Запуск в режиме разработки
```bash
npm run dev
```
Приложение откроется по адресу: **`http://localhost:5173`**

### 3. Демо-аккаунты (только в режиме Mock API)

Пароль для всех демо-аккаунтов: `Password123!`. На странице входа есть кнопки быстрого выбора, а в верхней панели — переключатель «Демо: сменить роль» (выполняет настоящий вход под соответствующим аккаунтом).

| Роль | Email |
| :--- | :--- |
| Администратор организации | `admin@corp.iclever.ai` |
| HR / менеджер обучения | `hr@corp.iclever.ai` |
| Руководитель подразделения | `manager@corp.iclever.ai` |
| Корпоративный тренер | `trainer@corp.iclever.ai` |
| Сотрудник | `employee@corp.iclever.ai` |

Также поддерживается регистрация новой организации (`/register`) и принятие приглашений по ссылке (`/invite?token=…`).

## ⚙️ Режим Mock API

Поведение API регулируется переменной окружения `VITE_USE_MOCK` (см. [`.env.example`](.env.example)):

* `VITE_USE_MOCK=true` *(по умолчанию)* — запросы `/api/v1/*` обрабатывает встроенный эмулятор бэкенда. Данные хранятся в `localStorage` браузера (`iclever_mock_db`, схема версионирована, старые данные мигрируются без потерь). Эмулятор реализует правила из `API_CONTRACTS.md`: серверные сессии, изоляцию организаций, RBAC, валидацию, журнал аудита, ограничение частоты запросов.
* `VITE_USE_MOCK=false` — модуль эмулятора не загружается, запросы уходят на реальный бэкенд (`VITE_API_BASE_URL`). Демо-аккаунты и переключатель ролей при этом не отображаются.

Модули контента (материалы, треки, когорты, назначения, банк вопросов, карточки, история отчётов) пока не имеют серверного API в этом репозитории: их данные хранятся в браузере в разрезе организации и помечены в интерфейсе значком «Демо-данные».

## 🌐 Локализация (ru / kk / en)

* Каталоги переводов: `src/locales/<язык>/<раздел>.json` (одинаковый набор ключей для `ru`, `kk`, `en`). Каждый язык загружается одним отдельным чанком по требованию.
* Движок: `src/kit/i18n/` — интерполяция `{{name}}`, множественные формы по правилам CLDR (`one/few/many/other` для русского, `one/other` для казахского и английского), форматирование дат, чисел и процентов через `Intl`.
* Выбор языка: переключатель RU / KK / EN в верхней панели и на страницах входа и регистрации. Порядок определения языка: сохранённый в профиле пользователя → явный выбор на устройстве → язык организации по умолчанию → язык браузера → `ru`.
* Динамический контент (названия подразделений, треков, материалов, вопросы тестов) хранится по языкам (`{ ru, kk, en }`); при отсутствии перевода показывается вариант на другом языке с пометкой для администратора.
* AI-функции (ассистент, генерация треков и вопросов) получают язык явно и проверяют структуру ответа.
* Проверка полноты переводов: `npm run i18n:check` (недостающие и лишние ключи, пустые значения, переменные интерполяции, формы множественного числа, неизвестные ключи в коде, оставшийся в коде русский текст).

Чтобы добавить строку: добавьте ключ во все три файла `src/locales/{ru,kk,en}/<раздел>.json` и используйте `t('раздел.ключ')` из `useI18n()`.

## 🛡️ Безопасность и контроль доступа

1. **RBAC из единого источника** (`src/kit/auth/permissions.ts`, матрица из `API_CONTRACTS.md` §16.2): одни и те же правила используются маршрутами, навигацией и (эмулятором) бэкенда. Сокрытие кнопок не является защитой — каждая операция проверяется на сервере.
2. **Сессии**: случайные токены с ограниченным сроком действия, выход отзывает сессию, приостановка сотрудника завершает его сессии. Подмена роли через `localStorage` невозможна.
3. **Изоляция организаций**: все данные выбираются по организации из сессии; заголовок `X-Organization-ID` должен совпадать с сессией.
4. **Учётные данные**: пароли хранятся только в виде солёного хэша и никогда не возвращаются в ответах API; при входе одинаковая ошибка для неизвестного email и неверного пароля; ограничение числа попыток входа.
5. **CSV**: защита от формульных инъекций (CWE-1236) при экспорте, проверка строк при импорте.
6. **Заголовки** (nginx): `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy`.

## 🐳 Docker

The production image is a static build served by nginx (non-root, port `8080`). On every push to `main`, GitHub Actions builds it and publishes it to `ghcr.io/ksvtmr/corporate`.

```bash
# Run the published image
docker run -d -p 8080:8080 ghcr.io/ksvtmr/corporate:latest

# Or build and run locally
docker compose up --build
```

Open **http://localhost:8080**. `VITE_*` variables are baked in at build time, so to point at a real backend, build with `--build-arg VITE_USE_MOCK=false --build-arg VITE_API_BASE_URL=/api`.
