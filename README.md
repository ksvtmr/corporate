# iClever Corporate Frontend

Корпоративный веб-интерфейс для управления обучением, онбордингом сотрудников, оргструктурой и базой знаний организации в экосистеме **iClever.ai**.

Данный репозиторий представляет собой **автономное frontend-приложение**, независимое от бэкенда и инфраструктуры.

---

## 🚀 Быстрый старт (локальная разработка)

Для локального запуска и тестирования интерфейса **не требуется** запускать микросервисы бэкенда или Docker. Все API-взаимодействия обслуживаются встроенным эмулятором (**Mock API Engine**).

### 1. Установка зависимостей
```bash
npm install
```

### 2. Запуск в режиме разработки
```bash
npm run dev
```
Приложение откроется по адресу: **`http://localhost:5173`**

### 3. Тестовые учетные данные для входа
При запущенном Mock API в форму авторизации (`/login`) уже предзаполнены или доступны следующие данные:

* **Email**: `admin@corp.iclever.ai`
* **Пароль**: `Password123!`
* **Роль**: `Organization Admin` (Компания: *Fintech Innovations Corp*)

Также поддерживается регистрация новой организации через форму `/register`.

## ⚙️ Управление режимом Mock API

Поведение API регулируется переменной окружения `VITE_USE_MOCK` в файле `.env` (см. [`.env.example`](.env.example)):

* `VITE_USE_MOCK=true` *(по умолчанию)* — все запросы `/api/v1/*` перехватываются встроенным Mock Engine (`src/mocks/`). Данные (новые сотрудники, созданные отделы, настройки) сохраняются в браузере (`localStorage`).
* `VITE_USE_MOCK=false` — запросы перенаправляются на реальный бэкенд / API Gateway (`http://localhost:8080`).

## 🛡️ Безопасность и контроль доступа (Security Architecture)

1. **Маршрутизация с RBAC-контролем (`<RequireRole />`)**:
   * Все защищенные разделы обернуты в компонент `<RequireRole allowedRoles={[...]}>`.
   * При попытке прямого ввода URL непривилегированной ролью (например, `employee` запрашивает `/corporate/settings` или `/corporate/integrity`) доступ блокируется с выводом экрана `403 Forbidden` и возможностью перехода в доступный раздел.
2. **Защита от утечки учетных данных**:
   * Пароли и хэши учетных записей исключены из всех DTO и API-ответов (`login`, `register`, `me`).
3. **Защита от CSV Formula Injection (CWE-1236)**:
   * Все экспортируемые ячейки экранируются и очищаются от опасных символов формул (`=`, `+`, `-`, `@`, `\t`, `\r`), исключая исполнение стороннего кода в табличных процессорах.
4. **Защитные заголовки и валидация**:
   * Предотвращение CRLF / HTTP Response Splitting в заголовках `ApiClient`.
   * Метатеги `nosniff`, `referrer-policy` и `X-XSS-Protection`.

---

## ⚡ Оптимизация сетевых запросов и производительность

1. **Дебаунс поисковых фильтров (`useDebounce`)**:
   * Все текстовые поля поиска (сотрудники, база знаний, банк вопросов) используют хук `useDebounce(..., 300)` — запросы отправляются только после завершения ввода, устраняя лавину запросов на каждый символ.
2. **Предотвращение состояний гонки (Race Conditions Guard)**:
   * Реализовано версионирование и отслеживание активного ID запроса: запоздавшие ответы на более ранние поисковые фильтры автоматически отбрасываются.
3. **In-Memory кэширование и дедупликация в `ApiClient`**:
   * Идемпотентные `GET`-запросы справочников кэшируются в памяти с TTL 15 секунд.
   * Одновременные одинаковые параллельные запросы объединяются через in-flight promise sharing.
   * Мутирующие запросы (`POST`, `PUT`, `DELETE`, `PATCH`) мгновенно инвалидируют кэш.
4. **Code-Splitting (Lazy Loading) страниц**:
   * Все 18 страниц переведены на `React.lazy` и `Suspense`. Стартовый размер бандла сокращен в 2 раза (с 451 кБ до 223 кБ).

## 📁 Структура проекта

```
.
├── src/
│   ├── components/layout/   # Компоненты разметки (сайдбар, хедер, свитчер тенанта)
│   ├── kit/                 # UI-кит (Button, Input, Card, Modal, Table, Badge, Auth, RequireRole, useDebounce, Tokens)
│   ├── mocks/               # Локальный Mock API движок (seed-данные, хранилище, адаптер)
│   │   ├── data/            # Исходные демо-данные (пользователи, сотрудники, отделы)
│   │   ├── adapter.ts       # Перехватчик fetch-запросов с санитизацией пользователей
│   │   └── store.ts         # Реактивное хранилище состояния с защитой от CSV-инъекций
│   ├── pages/               # 18 модулей приложения (lazy chunks)
│   ├── App.tsx              # Маршрутизация с RBAC guard и Suspense
│   └── main.tsx             # Точка входа, инициализация моков
├── API_CONTRACTS.md         # Полная документация контрактов для бэкенда
├── index.html               # Главный HTML шаблон с защитными метатегами
├── vite.config.ts           # Конфигурация Vite и алиасов путей
├── tailwind.config.js       # Дизайн-система Tailwind CSS
└── package.json             # Зависимости и скрипты
```

## 🐳 Docker

The production image is a static build served by nginx (non-root, port `8080`). On every push to `main`, GitHub Actions builds it and publishes it to `ghcr.io/ksvtmr/corporate`.

```bash
# Run the published image
docker run -d -p 8080:8080 ghcr.io/ksvtmr/corporate:latest

# Or build and run locally
docker compose up --build
```

Open **http://localhost:8080**. `VITE_*` variables are baked in at build time, so to point at a real backend, build with `--build-arg VITE_USE_MOCK=false --build-arg VITE_API_BASE_URL=/api`.
