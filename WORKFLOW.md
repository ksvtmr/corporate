# Как работать с проектом через Claude Code — пошаговая инструкция

Эта инструкция для тех, кто не занимается DevOps каждый день. Технические подробности — в [`DEPLOYMENT.md`](./DEPLOYMENT.md).

## Три места, где «живёт» сайт

| | Где | Кто видит | Как туда попасть |
| :--- | :--- | :--- | :--- |
| 🖥️ **Локально** | `http://localhost:5173` на вашем компьютере | только вы | `npm run dev`, изменения видны сразу после сохранения файла |
| 🔎 **Превью** | `https://ksvtmr.github.io/corporate/pr-<номер>/` | все, у кого есть ссылка | открыть Pull Request; ссылка появится комментарием в PR |
| 🌍 **Рабочий сайт** | `https://ksvtmr.github.io/corporate/` | все | нажать **Merge** в Pull Request |

Что происходит **автоматически**: проверки и тесты, сборка, публикация превью, комментарий со ссылкой, публикация рабочего сайта после merge, проверка сайта после публикации, удаление превью после закрытия PR.

Что делаете **вы**: просите Claude Code внести изменение, смотрите результат, открываете PR и нажимаете **Merge**, когда всё устраивает.

## 1. Открыть проект

**В облаке (claude.ai/code)** — проект уже открыт. Claude работает в отдельной ветке (например, `claude/...`).

**На своём компьютере** (нужны Git и Node.js 20+):

```bash
git clone https://github.com/ksvtmr/corporate.git
cd corporate
npm install
claude            # запустить Claude Code в папке проекта
```

## 2. Запустить локальный просмотр

```bash
npm run dev
```

Больше ничего запускать не нужно: бэкенд встроен (Mock API работает прямо в браузере). Окно терминала с `npm run dev` должно оставаться открытым, пока вы смотрите сайт. Остановить — `Ctrl+C`.

Если нужно открыть сайт с телефона в той же Wi-Fi-сети: `npm run dev:lan` (адрес `Network: http://192.168…:5173` появится в терминале). Не открывайте dev-сервер в интернет — для показа другим людям есть превью.

## 3. Где найти адрес

В терминале после запуска появится:

```
  ➜  API:     built-in Mock API (VITE_USE_MOCK=true), no backend required
  ➜  Local:   http://localhost:5173/
```

Откройте **http://localhost:5173** в браузере. Войти можно любым демо-аккаунтом (кнопки на странице входа), пароль `Password123!`, например `admin@corp.iclever.ai`.

> В облачной сессии Claude Code сервер запускается внутри облачного контейнера, и `localhost` вашего браузера к нему не подключён. Там Claude проверяет страницы сам (автоматический браузер), а вы смотрите результат на **превью**.

## 4. Попросить Claude Code изменить страницу

Пишите обычным языком, называя страницу и желаемый результат. Примеры:

* «На странице сотрудников (`src/pages/EmployeesPage.tsx`) добавь фильтр по подразделению».
* «Поменяй текст подзаголовка на странице входа на "Добро пожаловать" на всех трёх языках».
* «На дашборде сделай карточки в две колонки на телефоне».

Полезно добавить: «проверь в браузере», «запусти тесты», «добавь переводы для ru/kk/en». Тексты интерфейса лежат в `src/locales/ru|kk|en/*.json`, страницы — в `src/pages/`, общие компоненты — в `src/kit/`.

## 5. Видеть изменения без пересборки

Пока работает `npm run dev`, браузер обновляется сам (горячая перезагрузка, HMR):

* изменения страниц и компонентов появляются за секунду, **введённые в форму данные сохраняются**;
* изменения текстов в `src/locales/*.json` тоже появляются без перезагрузки;
* изменения стилей (классы Tailwind) применяются сразу.

Перезапускать `npm run dev` нужно только после изменения `vite.config.ts`, `.env.local` или установки новых пакетов.

## 6. Запустить проверки

```bash
npm run check        # всё сразу: lint, типы, переводы, тесты, сборка (~30 секунд)
npm run lint         # стиль и типичные ошибки кода
npm run i18n:check   # все ли тексты переведены на ru / kk / en
npm test             # unit и интеграционные тесты
npm run test:e2e     # сквозные сценарии в браузере (нужен Chromium: npx playwright install chromium)
```

Или просто попросите Claude: «запусти все проверки».

## 7. Сохранить изменения в Git

```bash
git status                      # какие файлы изменились
git add -A                      # подготовить все изменения
git commit -m "Фильтр по подразделению на странице сотрудников"
```

В облачной сессии достаточно сказать Claude: «сделай коммит».

## 8. Отправить изменения на GitHub

```bash
git push -u origin <имя-ветки>      # например: git push -u origin feature/department-filter
```

Работайте **в отдельной ветке**, а не в `main`:

```bash
git checkout -b feature/department-filter     # создать ветку для новой задачи
```

В облаке: «запушь изменения» — Claude отправит их в свою ветку.

## 9. Открыть и проверить превью

1. На GitHub: **Pull requests → New pull request**, base: `main`, compare: ваша ветка → **Create pull request**. (Или попросите Claude: «создай pull request».)
2. Подождите 4–6 минут. Внизу PR видны проверки: жёлтый кружок — идут, ✅ — прошли, ❌ — ошибка.
3. Когда всё зелёное, в PR появится комментарий **«🔎 Preview deployed: https://ksvtmr.github.io/corporate/pr-N/»**. Откройте ссылку.
4. На превью внизу слева жёлтый значок **«Тестовая версия»** — так вы его не перепутаете с рабочим сайтом. Данные превью хранятся отдельно и не трогают рабочий сайт.
5. Каждый новый push в эту ветку автоматически обновляет то же превью.

## 10. Опубликовать на рабочем сайте

В PR нажмите **Merge pull request → Confirm merge**. Дальше автоматически:

1. проверки повторяются на `main`;
2. сайт публикуется на `https://ksvtmr.github.io/corporate/`;
3. smoke-тест открывает опубликованный сайт и проверяет вход и страницы;
4. превью этого PR удаляется.

Через ~5 минут откройте рабочий сайт (если видите старую версию — обновите страницу с `Ctrl+Shift+R`).

## 11. Посмотреть логи деплоя

GitHub → вкладка **Actions** → workflow **CI/CD** → нужный запуск → джоба (**Deploy production** / **Deploy preview**) → разверните шаг. Ошибка выделена красным. История публикаций: **Code → Environments** (справа) → `production` или `preview`.

Claude тоже может посмотреть: «посмотри, почему упал деплой».

## 12. Откатить неудачный релиз

**Быстро, за 1–2 минуты:** GitHub → **Actions → Rollback production → Run workflow** → оставить поле пустым → **Run workflow**. Сайт вернётся к предыдущей версии.

**Затем исправить код** (иначе следующий merge снова опубликует ошибку): попросите Claude «откати коммит <описание> через revert и открой PR» или исправьте ошибку в новой ветке.

## 13. Если что-то не работает

| Проблема | Что сделать |
| :--- | :--- |
| `npm run dev` пишет `Port 5173 is already in use` | dev-сервер уже запущен в другом окне — откройте http://localhost:5173 или закройте то окно |
| Страница не обновляется сама | проверьте, что терминал с `npm run dev` не показывает ошибку; обновите страницу вручную (`F5`); если меняли `.env.local`/`vite.config.ts` — перезапустите `npm run dev` |
| Красный экран ошибки в браузере | в нём указан файл и строка; сообщите Claude текст ошибки |
| `✖ VITE_USE_MOCK=false but no backend is configured` | в `.env.local` выключен Mock API; верните `VITE_USE_MOCK=true` или укажите `DEV_API_PROXY_TARGET` |
| `npm run check` / CI красный | откройте Actions → упавший шаг; или попросите Claude «почини проверки». Сломанная версия **не** публикуется |
| Превью не появилось | проверки ещё идут или упали — смотрите внизу PR; превью есть только у PR в `main` из веток этого репозитория |
| Деплой production упал на smoke-тесте | сайт мог обновиться с ошибкой — сразу выполните откат (пункт 12), затем разбирайтесь с логом |
| На рабочем сайте старая версия | подождите 1–2 минуты (кэш GitHub Pages) и обновите страницу `Ctrl+Shift+R` |
| После публикации у кого-то «не грузится раздел» | у пользователя была открыта старая версия — достаточно обновить страницу |
