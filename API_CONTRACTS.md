## 1. Architectural Conventions & Global Standards

### 1.1 Base URL & Routing
All frontend requests target the API Gateway reverse-proxy routes under `/api/v1`:
```
https://<domain>/api/v1/<service-prefix>/<resource>
```
During local development without backend services, all endpoints defined in this document are intercepted and served by the built-in Frontend Mock Engine (`src/mocks/`).

### 1.2 Mandatory HTTP Headers
| Header Name | Type | Requirement | Description |
| :--- | :--- | :--- | :--- |
| `Authorization` | `string` | Mandatory on protected routes | Standard Bearer JWT: `Bearer <token>` |
| `X-Organization-ID` | `UUID` | Mandatory on corporate routes | Active organization/tenant context |
| `X-Correlation-ID` | `string` | Generated by frontend | Request tracing identifier (`req-<rand>-<timestamp>`) |
| `Content-Type` | `string` | Mandatory (`application/json`) | Except file uploads (`multipart/form-data`) |

### 1.3 Universal Response Envelope
All REST API endpoints MUST return responses wrapped in the standardized envelope:

#### Successful Response (`200 OK` / `201 Created`):
```json
{
  "success": true,
  "data": { ... },
  "meta": {
    "page": 1,
    "limit": 20,
    "total_items": 142,
    "total_pages": 8
  }
}
```

#### Error Response (`4xx` / `5xx`):
```json
{
  "success": false,
  "error": {
    "code": "INVALID_CREDENTIALS",
    "message": "Неверный email или пароль",
    "details": {},
    "support_id": "req-98x7a-1725300000"
  }
}
```

### 1.4 Standard Error Codes
| HTTP Status | Error Code | Description |
| :--- | :--- | :--- |
| `400 Bad Request` | `BAD_REQUEST` | Malformed JSON or invalid query parameter |
| `401 Unauthorized` | `UNAUTHORIZED` | Expired or missing Bearer JWT token |
| `403 Forbidden` | `FORBIDDEN` | Insufficient RBAC permission or cross-tenant violation |
| `404 Not Found` | `NOT_FOUND` | Requested entity does not exist in current tenant |
| `409 Conflict` | `USER_EXISTS` / `CONFLICT` | Unique constraint violation (e.g. duplicate email) |
| `422 Unprocessable`| `VALIDATION_ERROR` | Field validation failed |
| `500 Server Error` | `INTERNAL_ERROR` | Internal server or unhandled database exception |

## 16. Security & Multi-Tenancy Architecture Specifications

### 16.1 Tenant Isolation & IDOR Protection
1. **Mandatory Header & JWT Matching**:
   * Every non-public corporate request MUST carry `X-Organization-ID: <UUID>`.
   * The API Gateway and downstream services MUST verify that the authenticated user's JWT contains an active membership in the requested `organization_id`.
   * Any mismatch between `X-Organization-ID` and the signed JWT claims MUST immediately return `403 FORBIDDEN` (error code: `TENANT_ACCESS_DENIED`).
2. **Database Scoping**:
   * All SQL/ORM queries must enforce `WHERE organization_id = $tenant_id` at the repository/middleware layer.

### 16.2 Complete RBAC Matrix
| Module / Capability | `platform_super_admin` | `org_admin` | `hr_manager` | `trainer` | `manager` | `employee` |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **Org Settings & Branding** | Full | Full | Read/Write | Forbidden | Forbidden | Forbidden |

### 16.3 Sensitive Data Protection & Redaction
* **Zero Credential Exposure**: Passwords, password hashes, and salts MUST NEVER be included in any API response envelope (`SeedUser`, `User`, `OrgMember`).
* **Header Sanitization**: All client and server header values must strip CRLF characters (`\r`, `\n`) to prevent HTTP Response Splitting attacks.

### 16.4 Protection Against CSV Formula Injection (CWE-1236)
* When exporting CSV data (`/api/v1/corporate/members/export` or `/api/v1/exports/jobs`), any cell starting with `=`, `+`, `-`, `@`, `\t`, `\r` MUST be prefixed with a single quotation mark `'` to ensure spreadsheet software treats the content strictly as text and does not execute arbitrary formulas.

### 16.5 Rate Limiting Policies
* **Public Auth Endpoints** (`/identity/login`, `/identity/register`): Max 10 requests / minute per IP.
* **Corporate Standard API**: Max 120 requests / minute per authenticated user token.
* **AI Generation & Chunker Endpoints**: Max 20 requests / minute per organization.
* Exceeding limits returns `429 Too Many Requests` with `Retry-After: <seconds>` header.

## 17. Query Optimization & Performance Standards

### 17.1 Pagination Standards
* Default page size: `20` items. Maximum allowed limit: `100` items.
* Response metadata envelope MUST include:
  ```json
  "meta": { "page": 1, "limit": 20, "total_items": 142, "total_pages": 8 }
  ```
* High-volume append-only streams (e.g. Integrity Events) support Keyset Cursor pagination (`?after_id=<UUID>&limit=50`).

### 17.2 Caching & ETag Standards
* Static dictionaries (Departments, Job Positions, System Settings) return HTTP `ETag` and `Cache-Control: private, max-age=60`.
* The Frontend `ApiClient` implements in-memory caching with 15-second TTL and automatic in-flight promise deduplication for concurrent `GET` requests.
* Any mutating operation (`POST`, `PUT`, `DELETE`, `PATCH`) automatically invalidates the client cache.

### 17.3 Client Search Debounce
* All client-side text search inputs (e.g. employee search, question bank search) MUST implement debouncing with a minimum threshold of `300ms` via `useDebounce()`, preventing query flooding during active keystrokes.
